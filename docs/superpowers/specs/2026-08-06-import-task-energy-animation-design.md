# 匯入任務與能量球動效設計

## 目標

瀏覽器選檔與 Windows 右鍵匯入共用同一後端任務隊列。日曆工具列顯示最多三個正在處理或需處理的文件項目；AI 分析完成並成功寫入本地日曆時，從對應項目發射主題色能量球，沿拋物線命中可見日期格。

## 任務生命週期

- 每份文件建立一個匯入任務，狀態為 `QUEUED`、`ANALYZING`、`COMPLETED` 或 `FAILED`。
- 後端在瀏覽器和桌面入口之間合計最多同時分析三份文件；其他任務按提交順序等待。
- 隊列只存在於後端進程記憶體，重啟後不恢復。
- 分析中的任務不能取消。失敗任務保留錯誤摘要，允許重試或關閉。
- 成功任務由瀏覽器寫入 localStorage/IndexedDB；第一顆能量球開始時任務項目關閉並向後端確認收取。

## API 契約

- `POST /api/imports`：multipart 上傳 `file`、`calendars`、`profile`，回傳 `202 { task }`。
- `GET /api/imports`：回傳 `{ imports }`，依建立時間排序。完成任務包含 `events` 與 `extractedText`。
- `POST /api/imports/:id/retry`：只重試 `FAILED` 任務，回傳 `202 { task }`。
- `POST /api/imports/:id/ack`：移除 `COMPLETED` 或 `FAILED` 任務，回傳 `{ ok: true }`。
- 所有端點沿用 Origin 白名單與 `X-Proxy-Key`；錯誤保持 `{ error: { message } }`。
- `/api/documents/analyze` 保持同步分析相容行為；桌面腳本改用 `/api/imports`。

## 工具列任務列

- 文件選擇器支援一次多選，分析期間仍可再次選擇。
- 工具列在「匯入文檔」右側顯示最多三個任務項目；每項顯示依 MIME/副檔名選擇的文件圖標、截斷文件名與實際分析秒數。
- 排隊文件以「另有 N 份等待中」彙總；空位出現後按 FIFO 進入分析。
- 失敗項目顯示簡短錯誤、重試按鈕與關閉按鈕。
- 範圍只包含桌面版。

## 動效

- 同一文件每個不同日期發射一顆球；同日多事件合併。球之間以 100ms 間隔連射。
- 能量球從對應文件任務項目出發，沿拋物線飛行 650ms。
- 命中後用 250ms 完成壓縮回彈、單圈波紋與事件淡入。
- 可見月份內命中帶 `data-date-key` 的日期格。
- 非目前月份按月份合併為一顆球，命中月份導覽區並顯示「已加入 YYYY 年 M 月 · N 個事件」浮窗。
- 日間使用 `#0071e3`，黑夜使用 `#0a84ff`，由既有 `--color-accent` 自動切換。
- `prefers-reduced-motion: reduce` 下不播放飛行，只短暫高亮目標並顯示跨月份浮窗。

## 錯誤與一致性

- 單個任務失敗不阻塞其他任務。
- 文件結果只有在本地事件入庫成功後才 ACK；入庫失敗時保留任務以便重試。
- 多分頁原子認領尚未納入本次範圍，維持目前 README 已記錄的多分頁限制。

## 驗收

- 同時提交四份文件時，後端最多三份為 `ANALYZING`，至少一份為 `QUEUED`。
- 瀏覽器和桌面提交出現在同一任務列表。
- 多選、追加選檔、等待計數、失敗重試和關閉均可操作。
- 成功入庫後，能量球從正確任務項目命中每個唯一可見日期；跨月份顯示正確浮窗。
- 日夜色票與 reduced-motion 行為符合既有主題約定。
